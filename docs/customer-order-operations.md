# 客户支付与生成入口接入（T01 / T02）

日期：2026-11-06。开发分支 `codex/admin-console`，从 `3193616` 继续。
本轮完成代码接入与隔离验证；生产迁移、真实 PayPal/模型验收及正式发布另行安排。

## 支付（T01）

- 新增 `POST /api/paypal/quote`。歌词页通过明确的 POST 保存报价，显示、创建和捕获
  使用同一份整数美分、币种和支付环境快照；订单 GET 不创建报价或 PayPal 订单。
- 报价沿用已验证用户的服务器价格规则；客户端传入的价格/环境不参与定价。
- 创建、捕获分别使用稳定的 PayPal 请求键。已关联的结账先读原 PayPal 订单，
  不重复创建；数据库绑定只接受首次或同号重放，不覆盖另一笔结账引用。
- PayPal API 和凭据按报价中的环境选择。当前默认价格/环境变更不影响既有报价。
- 捕获前后读取 PayPal 事实：一组匹配 purchase unit、单笔 COMPLETED/final capture、
  Capture ID、金额、币种和供应商时间；通过事务写入流水及 paid_at，不回退交付状态。
- 捕获响应丢失时先读原订单，不在该请求内再次捕获。网络/配置错误不输出供应商原始响应。
- 缺少可信报价的历史结账保持待核实，不按当前价格补猜测。新生产生成需有匹配捕获流水，
  仅凭旧 paid_at 不启动新的付费生成；已有历史歌曲继续可播放。

## 生成与保存（T02）

- 只有原子预留返回 created=true 时才能调用生成接口；同一订单使用稳定提交键。
- 在锁定订单的事务中保存输入快照（确认歌词、收礼人、故事、场景、曲风等）及所请求
  的供应商/模型。任务开始后冻结相应订单输入；歌词编辑同时使用数据库条件阻止竞态覆盖。
- 客户提交、状态查询和结果保存共用 generation_jobs/租约。后续查询按任务记录选供应商
  和模型，不根据当前默认值切换，也不因原供应商配置故障转成 mock。
- 新订单保存 active_generation_job_id。页面可用内部任务 ID 查询没有外部任务号的同步
  返回结果；客户端得到白名单进度，不得到租约、提交令牌、输入快照、源地址或 base64。
- 完成结果先在 service-only 的 generation_job_outputs 保存最小恢复来源。异步任务缓存
  HTTPS 音频地址，同步任务临时缓存 base64；成功交付后在完成事务内删除缓存。
- 音频限制为 32 MiB，识别 WAV/MP3/Ogg/FLAC/MP4 文件头；无效内容不能登记为成品。
  源下载有超时和大小限制，自动重定向关闭；供应商直链需可直接读取。
- 上传路径为 orderId/jobId/final.ext，禁止覆盖。确认同一路径已存在后读取并比较原音频；
  上传成功但登记失败时保留对象，下一次租约恢复不会新建文件或重新调用生成。
- complete_songgift_audio 在租约有效时原子登记最终资产、完成任务、更新订单和追加事件，
  失败整体回滚。新流程不会向用户暴露“已登记资产但订单尚未完成”的中间状态。
- 保存失败保持 storing，并写入可供现有概览/订单异常筛选识别的通用标记；成功恢复清除标记。
  已知异步任务可重新读取结果以更新过期源地址；缓存里的同步音频可直接恢复保存。
- 提交结果不明、无任务号且未能持久化同步结果时进入 needs_review，不自动重新生成。
  初次缓存本身失败且没有可查询引用时无法承诺自动恢复，需人工核实。

T01/T02 原始阶段只由客户请求推动查询。后续 T03–T05 已加入管理员操作、独立定时 Worker
和通知发件箱，见 [交付处理](delivery-operations.md)；代码接入不代表已发布生产。

## 增量迁移

现有安装按顺序应用：

1. 20261105_admin_permissions.sql
2. 20261105_admin_audio_audit.sql
3. 20261105_order_operations.sql
4. 20261106_customer_order_operations.sql（本轮新增）

supabase/schema.sql 同步新安装结构。新增结构缺失时客户写入口拒绝处理，不回退到旧的
无流水/租约流程；部署需先验证迁移和兼容步骤。不要在第 4 步后重跑旧业务基础迁移覆盖
已更新函数。回退应用也必须评估旧付款/生成入口的兼容性，保留流水、任务、缓存和音频。
历史报价、输入快照和任务外键不补猜测，历史资产不搬迁、不删除；历史在途任务未自动
导入新任务表，新增恢复操作前需单独核实。真实 Owner 授权规则保持原样。

## 隔离验证

- npm run test:customer：真实内存 PostgreSQL schema/RPC + 模拟 Supabase 传输和外部服务。
  覆盖报价冻结、结账复用、完整捕获证据、跨账户拒绝、并发提交/查询、输入冻结、任务路由、
  失效租约、未知提交、缓存/上传/登记故障、源 URL 更新、同步音频恢复及完成幂等。
- npm run test:admin：现有后台回归，另覆盖从上一版结构增量升级且不推断历史数据。
- scripts/test-customer-runtime.mjs：仅接受回环目标；serve 提供假 Auth、PostgREST、Storage
  和音乐响应，test 通过实际应用路由验证客户链路。测试不读取 .env，不发送验证码邮件。
- 运行应用时必须显式设置 SUPABASE_URL=http://127.0.0.1:54330、假 publishable/service
  key，MUSIC_PROVIDER=google_lyria、假 Google 凭据，并将 GOOGLE_LYRIA_ENDPOINT 指向
  http://127.0.0.1:54330/music-fixture。真实生产配置不能用于此测试。
- 本地 Next 与 Workers 各 12 项客户运行时检查；桌面/手机浏览器验证固定报价、歌词保存
  恢复、生成跳转、实际 WAV 解码播放和布局。音频是人工构造的短测试音，不是生成歌曲。

登录 SMTP、真实 PayPal Live 收款、外部模型服务、真实歌曲的演唱/歌词准确度都不由上述
夹具证明。真实歌曲验收应核对收礼人姓名发音、语言、确认歌词、曲风和完整性；模型状态
与文件头只能用于技术交付验收。本轮没有引入自动歌曲质量评分。
