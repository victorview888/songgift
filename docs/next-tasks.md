## 对歌曲业务的适用性

本清单主要完善歌曲下单、生成交付和运营流程；歌曲的旋律、演唱和歌词表现还需要
按真实音乐模型的能力验收。任务都按歌曲业务适配，优先级不同：

| 任务 | 歌曲业务中的作用 | 优先级 |
| --- | --- | --- |
| T01–T05 | 收款与生成对应、避免重复付费生成、保存并交付音频、恢复异常和通知买家 | 核心交付优先 |
| T06 | 客服查单、定位生成故障、追溯管理员处理 | 运营配套；底层审计随操作接入，独立页面可随后补齐 |
| T07–T08 | 保护填写中的故事，便于将成品送给收礼人 | 体验改进；草稿可穿插，分享在交付稳定后开展 |
| T09–T10 | 内容获客和分析下单转化 | 增长任务，按推广节奏安排 |
| T11 | 付款记录、帮助和账户补充 | 客服及退款/保存说明随付费交付完善；高级账户功能后续按需 |

歌曲业务需保留自己的边界：失败重试首先恢复查询和音频保存，未知提交不得自动重发；
退款和重新生成单独制定规则，不套用视频退积分机制。音频保存/到期规则按歌曲赠礼
承诺设计，不沿用模板的视频清理期限；赠礼链接须由购买者主动开启。

## 第一批：接通现有业务入口（代码及隔离技术验收完成）

实现及新增迁移见 [客户入口接入](customer-order-operations.md)；真实服务与歌曲内容验收仍待安排。

### T01 支付报价与捕获接入

- [x] checkout 先保存不可变报价、币种、环境，再创建 PayPal 订单，使用稳定请求键。
- [x] 展示、下单和捕获均读取同一报价；捕获核实归属、Capture ID、金额、币种及环境，事务记录流水和事件。
- [x] 保留历史未知金额；旧订单单独核实，不按当前价格回填。

验收：改价不影响既有报价；并发/重复请求不会重复记收款或覆盖交付状态；错金额、
错环境及跨账户请求被拒绝。使用隔离支付响应验证，真实 PayPal Live 验收另行安排。
实现前提及服务规则见 [order-operations.md](order-operations.md)。

### T02 生成提交、查询和音频保存统一接入

- [x] 生成前核实订单满足付款要求，固定本次确认的歌词与生成参数，便于核对实际提交内容。
- [x] 客户生成与状态入口共用任务预留和租约，按任务已记录的供应商/模型路由。
- [x] 提交结果不明进入待核查；只查询已知任务，不自动重新提交付费生成。
- [x] 所有音频保存入口接入确定对象路径、任务资产唯一约束和完成事务。
- [x] 恢复“供应商成功但上传失败”“上传成功但登记失败”，不另发生成请求。
- [x] 同步更新订单、任务、详情和经营概览的状态解释与筛选口径。
- [x] 完成技术音频检查，并用隔离 WAV 验证访问/播放。
- [ ] 按后续明确授权，用实际生成歌曲核对歌词、收礼人姓名、语言、曲风和歌曲完整性。

验收：客户轮询与后台并发只形成一份最终资产；失效租约不能提交结果；保存失败
可恢复，未知提交不会重发。通过音乐/Storage 隔离端到端验证后，进入 T03/T04。
音频记录或模型 completed 状态不能单独证明歌曲可播放或内容合格。时长、姓名发音、
逐字演唱和曲风符合程度需按实际供应商能力验收，不能仅凭提示词保证；首版不引入
自动音乐评分系统。真实歌曲样本验收按后续明确授权安排，不自动调用付费模型。

## 第二批：交付恢复与自动处理

### T03 管理员受控处理

依赖 T01/T02。复用模板操作区和反馈交互，新增：

- [ ] 核对 PayPal 既有付款事实；只读查单不代替捕获，不手工标记已付款。
- [ ] 同步原生成任务；不触发新一轮生成。
- [ ] 恢复既有结果的音频保存。

验收：每次操作重新鉴权，执行前持久化审计请求；重放请求不重复操作，成功失败均
可追溯。没有可信外部证据时保持待核查，不直接改成已完成。不包含退款和重新生成。

### T04 服务器自动交付

依赖 T02。借鉴模板队列、定时维护、退避重试和异常兜底，结合现有部署方式选择调度入口。

- [ ] 定期领取可处理任务，共用客户/管理员的租约及保存服务。
- [ ] 用户关闭网页后仍能查询任务、保存结果并完成交付。
- [ ] 设置单批上限、超时、退避和待核查规则；记录最近处理时间和错误类别。

验收：重复调度、进程中断、供应商限流和短时存储故障可恢复；没有无限轮询和未知
提交重发。模板的视频失败退积分逻辑不迁入歌曲订单。

### T05 歌曲通知

依赖 T02 的明确完成事件，可在 T04 后接入自动交付。复用模板发件箱、事件去重和重试流程。

- [ ] 接通歌曲完成通知；后续按业务规则补充需要人工处理等通知。
- [ ] 通知写入持久化发件箱，重试与业务处理分离，失败不撤销歌曲交付。
- [ ] 邮件跳转到可重新鉴权的稳定歌曲页面，避免把短期音频签名链接作为长期入口。

验收：同一事件只产生一条通知任务；临时失败可退避重试，最终失败可查。
发件箱去重不等于邮件服务绝对只投递一次，需核对服务商幂等能力。
登录验证码邮件沿用现有 Supabase SMTP，系统诊断与歌曲通知配置分开显示。
