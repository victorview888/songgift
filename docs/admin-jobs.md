# 生成任务查询页（第一版）

后续 T03–T05 已在订单详情加入受控同步/保存，并新增自动交付与通知，见
[交付处理](delivery-operations.md)。下文记录原只读查询页范围，查询页仍保持只读。

`/admin/jobs` 和 `GET /api/admin/jobs` 已实现只读查询，沿用服务端 Owner 检查、
private/no-store、noindex，以及现有后台布局、筛选、分页、状态和刷新组件。
界面组合改编自 ShrimpReel `e1447714d61eb67af653c931e917dce7b63012b0` 的
`src/routes/admin/generations.tsx`；MIT 版权及完整许可保留在第三方目录。

## 两种来源

| source | 内容 | 数据前提 |
| --- | --- | --- |
| legacy（默认） | 订单最新任务引用，或本地标记 generating/failed/completed 的订单；一笔订单一行 | 原有订单和资产表，无需本轮新增迁移 |
| recorded | generation_jobs 中已登记的生成尝试，关联订单邮箱及收礼人 | 需第 13 阶段数据基础迁移；缺表返回 503，不显示假零 |

两种来源单独查询、计数、分页，不进行合并或相加，也不假装已经把旧任务导入新表。
新任务入口尚未接入数据基础，因此 recorded 不是现有全部任务的完整清单。
legacy 也包括无任务号但本地状态异常的候选订单，便于发现提交引用丢失。

legacy 不生成虚构任务 ID、环境、尝试次数或完成时间，也不从当前默认模型补历史值。
日期按订单创建时间筛选，不能据此计算等待时长。recorded 日期为任务预留时间；
预留后时长/预留至完成只根据已存时间计算，不等于供应商实际运行耗时。缺少失败结束
时间时不把失败任务持续计时，时钟异常也不显示负时长。时长随手动刷新更新。

## 查询参数

- `source`：legacy / recorded，默认 legacy。切换来源重置筛选。
- `searchBy`：orderId（默认）、email、providerJobId；jobId 仅限 recorded。
- `q`：完整精确匹配；邮箱不区分大小写，并转义 ilike 通配符。外部任务引用允许
  最长 2048 字符，通过 eq 传值，不能提供 SQL/OR 表达式。
- `state`：当前来源的状态集合；不能将订单 generating 当作任务 processing 互换。
- `provider`：fal / musicapi / mureka_cn / google_lyria / mock。
- `environment`：recorded 支持 production / test；legacy 拒绝该参数，避免推断环境。
- `attention=1`：recorded 为 failed / needs_review 或存在错误码；legacy 在任务候选中
  选无最终音频且本地失败、完成或存在生成错误的记录。候选集不同，不承诺等于全订单概览异常数。
- `from` / `to`：YYYY-MM-DD，北京时间双端日期包含，转换为 UTC 半开区间。
- `page`：1 至 999999，默认 1；每页 20 条，按来源时间及 ID 倒序，筛选后精确总数。

筛选与重置回到第一页，翻页保留条件。详情链接可返回 `/admin/jobs` 并保留任务来源、
筛选及页码；返回地址仍仅允许本地订单/任务列表，拒绝站外、API 和详情路径。
超长返回地址沿用 4096 字符限制，超出时回到订单列表。

## 权限与处理边界

页面先 await getAdminPageAccess，接口先进入 adminRoute，再解析参数和读取任何来源。
不存在前端自助提权、公开数据直查或测试登录应用路由；成员撤销后新请求即拒绝。
过滤条件无效返回 400，查询/缺表失败返回通用 503。正常空数据和超页为空状态，
不把数据故障当作没有任务。旧来源可在新表不可用时继续访问。

返回白名单摘要：订单/任务标识、订单邮箱、收礼人、记录中的供应商/模型、状态、
音频记录标记及时间。不得返回故事、歌词、租约/提交令牌、音频路径或签名 URL。
legacy 的原始 generation_error 只在服务端转为通用标记；未知错误码不原样输出。

本轮没有同步供应商、恢复音频保存、标记失败/完成、重新生成、退款或退积分操作。
没有调用外部模型、付款或发信服务，也没有执行生产迁移/授权。下一阶段必须先将
生成提交、查询和保存入口接入共享任务/租约/幂等服务，经过隔离验收后再添加明确的
同步原任务、恢复保存按钮。不能直接迁入模板的“标记失败并退积分”。

## 验证

单元/受控 Supabase 传输检查精确搜索、日期、分页、嵌套订单邮箱筛选、来源兼容性、
固定候选/异常条件组合、脱敏及缺表行为。服务端成员检查和撤权沿用现有权限测试。
运行时检查使用本机 Auth/PostgREST 测试夹具；结构化任务为模拟响应，不能证明
生产数据库或实际供应商记录已接入。客户 RLS 和音乐/支付实现均保持原有边界。
