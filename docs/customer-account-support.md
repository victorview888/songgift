# 用户中心与客服说明（T11 第一版）

更新：2026-11-06。基线 codex/admin-console / 6923f37，开始前工作区干净。
用户授权 T11；T06、T08、T09、T10 均暂停。本轮只补歌曲订单的客户入口。

## 页面与接口

| 页面 | 内容 |
| --- | --- |
| /account | 已验证的登录邮箱、退出、清除同标签页的未完成故事草稿 |
| /account/payments | 已保存报价或付款标记的本人订单，服务端每页 10 条 |
| /account/payments/[id] | 原始报价、已核实的捕获/退款记录、完整订单及交易参考号、浏览器打印 |
| /help | 登录、草稿、付款异常、生成进度及音频下载说明 |
| /contact | 客服邮箱及主题/订单号/正文表单，准备邮件草稿，由用户自行发送 |
| /policies/refunds | 查付款、提交问题和核对退款状态的流程说明 |
| /policies/audio-storage | 私有账户访问、临时音频链接及下载备份说明 |

My Songs 增加账户导航和各订单的付款记录链接；歌曲页提供付款记录和带订单号的联系入口；
首页底部链接帮助/联系/说明。没有新增分享授权、SEO 增长内容、归因或分析埋点。

GET /api/account/payments?page=0 与 GET /api/account/payments/[id] 复用 authRoute，
每次验证真实 Auth 用户及已验证邮箱，再约束 service-role 查询的 user_id。其他账户和
不存在的订单均返回相同 404；非法分页返回 400。响应 private/no-store，页面 noindex。
查询失败返回 503，前端显示错误及重试，不伪装为零条记录。

## 付款口径与最小字段

- 原始报价与交易实付分开；不读取当前价格来填历史记录。
- 实付仅来自 payment_transactions 的已登记捕获事实。paid_at 无交易时显示历史金额未核实。
- Sandbox 明确标为测试；退款独立列出，部分和全额退款区别展示，不冒充真实退款操作。
- 每笔订单最多读取最近 51 笔交易，返回其中 50 笔；超过上限提示记录不完整，不推算付款总额。
- 订单按 created_at 和 id 双重降序分页，包含已保存报价/历史付款，排除未报价的未付款草稿。
- 凭证只投影订单号、标题/收礼人、日期、原报价以及交易类别/参考号/金额/币种/环境/时间。
  不包含故事、歌词、邮箱、支付手续费、原始供应商数据、租约、内部日志或音频能力链接。
- 打印使用浏览器当前已鉴权记录，隐藏导航和操作按钮；不生成公开凭证 URL。
- 客户端请求按账户和路径隔离并取消旧请求；切换账户时不展示旧记录，迟到响应也不能覆盖。

未新增表、迁移、退款命令或外部对账。沿用既有支付迁移；生产缺少相关表/字段时明确失败，
不会读旧字段当作已核实交易。新增页面不自动执行付款、生成或发信。

## 账户与客服边界

账户页仅允许查看已验证邮箱、退出和明确确认后清除当前标签页草稿。清除存储失败时
如实提示；不会删除服务器订单、已购歌曲或音频。不提供无需验证的邮箱修改入口。
账户删除、数据导出及邮箱变更需先明确交易保留、订单归属和音频处理规则，仍待后续设计。

SONGGIFT_SUPPORT_EMAIL 是公开、能收信的客服地址，独立于 Supabase Auth SMTP 和
SONGGIFT_FROM_EMAIL。两类发信可以用同一地址，但发信域名/Resend 配置并不建立收信邮箱。
应先配置邮箱或转发并核实收信。用户尚未确认具体已开通地址；建议 support@songforalways.com，
不能把建议当作已启用配置。.env.example 保持空值。

客服配置只接受常规邮箱格式，不接受换行或 mailto 参数。未配置时说明客服邮件不可用并禁用
准备按钮，不回退到通知 sender。已配置时表单只在内存中生成 mailto 草稿和可复制文本，
用户再到邮件应用发送；不保存正文，不调用 Resend，不展示“已发送/已收到”。
订单 query 仅接受 UUID，不加载订单资料，不作为客服身份认证；正文以普通文本显示和编码。

具体退款条件、音频托管期限仍待经营者确定。本轮说明当前查单、复核和下载流程，
不编造退款时限、免费重做、托管天数或永久在线保证。发布前补最终业务约定；没有执行
生产迁移、真实邮件、付款/退款、付费生成、master 合并或部署。

## 隔离验证

- npm run test:account：真实内存 PostgreSQL 与 Supabase 客户端，覆盖鉴权/跨用户、
  最小投影、历史价格、未知金额、退款、稳定分页、故障、交易上限及客服配置注入。
- customer、drafts、admin、delivery 相关回归；lint、类型、Next Webpack 和 Workers 构建。
- node scripts/test-customer-runtime.mjs serve 提供明确假凭据的回环 Auth/数据库/Storage；
  SONGGIFT_ACCOUNT_TEST_URL=http://localhost:3002 node scripts/test-account-runtime.mjs
  验证真实接口及两种运行时。脚本拒绝非回环应用目标，不应针对生产执行。
- 桌面/手机验证导航、分页、凭证/打印、未知金额、联系客服预填、邮件草稿、缺失客服配置、
  空/错状态、重试、账户切换迟到响应、退出与草稿清理。全部使用假订单和隔离邮箱，
  没有实际发送邮件或把真实支付当作测试。
