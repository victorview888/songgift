## 回退边界

- 网站页面/接口可以切回已保存且经过兼容检查的 Worker 版本。优先使用 Cloudflare
  部署历史进行切换，并同步修正 GitHub master，防止下一次自动构建重新部署问题版本。
- 必须先停维护 Worker 和新付款/生成写流量，等待或核对正在执行的租约；单纯回退前端
  不会停止 Cron。若无法暂停写流量或无法证明旧 API 兼容，先修复新版，不能盲目回旧版。
- 数据库不做删除式回退：保留 payment_transactions、generation_jobs、输入快照、
  通知、审计、草稿请求及全部音频。新版已开始的任务不能交给旧入口盲目重发。
- 旧应用可能无法处理新版任务/报价。回退前核对未完成订单；必要时保持新接口处理这些
  订单，仅回退页面。代码回退并不保证全部新业务立刻恢复，也不撤销已发生的付款或发信。
- 只有确认数据损坏且核对备份之后才考虑数据库恢复；恢复可能丢失备份后的交易，
  必须重新对账。不能把数据库还原视为常规的一键回退。
- 维护 Worker 的开关和部署版本分别记录；生产密钥、环境变量、数据库及 Storage
  不会随网页版本自动恢复。恢复业务前重新核对它们。
