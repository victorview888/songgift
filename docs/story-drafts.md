# 故事草稿恢复（T07）

更新：2026-11-06。从 codex/admin-console / e5b8dff 继续。
按用户最新指示，本轮仅开发 T07；T06 和 T08 暂停。没有加入赠礼分享或公开歌曲入口。

## 浏览器草稿

/create 输入时同步保存收礼人、关系、场合、故事、情绪和曲风。沿用原来的同标签页
sessionStorage，新增版本、保存时间、账户归属、稳定故事请求号及已有订单续接标记。
有效期为最近编辑/提交后 24 小时；刷新不会仅因为读取而延长有效期。标签页关闭后
浏览器草稿不保证保留，已提交到账号的故事和订单仍留在服务器。

恢复前等待账户检查并校验字段类型、长度、版本、时间与 UUID。损坏、超长、过期或
其他账户的草稿不会自动恢复。访客草稿可在同标签页登录后绑定到已验证账户；已有
账户草稿仅供同一 UUID 恢复。旧格式没有归属/时间，只在未登录状态下迁移一次，
不把无归属旧内容自动导入另一已登录账号。

页面显示保存/恢复提示。存储受限时仍可填写，并提示离开前保留副本；账户绑定无法
持久化时清除未绑定副本，避免下一账户误恢复。退出登录清理新旧浏览器草稿并取消
当前页面请求；原账号数据不因迟到响应回写。账户刷新采用请求版本，阻止旧会话响应
覆盖较新的身份/退出状态。成功退出后以新文档返回首页，清除页面内存并避免私有页的
登录重定向争抢导航。服务端订单和已购歌曲不随本地清理删除。

## 续接与防重复

歌词保存后保留已有订单链接。返回 /create 时可继续已有歌词/付款流程，或明确选择
开始新故事；不因为页面恢复自动创建订单、捕获付款或提交歌曲生成。取消付款/返回歌词
仍使用原订单，沿用 T01 的 PayPal 关联和报价。

新客户端发送稳定 clientRequestId 与 draftOwnerId。服务端以真实 Auth 用户验证归属，
对规范化故事内容计算 SHA-256 指纹。song_story_requests 是 service-only 私有表，
不把写入租约放进客户可直读的订单表。

- 第一次请求在事务中创建 draft 订单并预留 5 分钟歌词写入租约，才调用歌词接口。
- 并发相同请求只启动一次歌词写入，返回同一个 orderId；已有歌词直接恢复。
- 同号不同内容拒绝覆盖；更换账户拒绝继续上一账户请求。
- 已知写入失败后，用户明确重试仍沿用原订单。不会自动重试外部模型。
- 写入结果不明且租约过期时保留故事并标为需协助，不自动再次调用模型；原订单可在
  My Songs 找到。新故事需要用户明确选择，不能用新请求号暗中补发。
- 短暂 pending 时，页面只读取既有订单检查歌词，不再次提交模型。
- 结果写回受租约保护，不覆盖并发保存的已确认歌词，不回退付款/生成状态。
- 保留未携带请求号的旧创建接口兼容；新的页面和恢复流程使用稳定请求号。绑定到
  新请求的订单，不接受旧接口按 orderId 改写故事；歌词编辑继续沿用原 PATCH 接口。

租约、内容指纹和原始供应商响应不返回客户端。保存/恢复仅处理故事到歌词阶段，
歌曲生成、支付和交付继续沿用 T01–T05；未调用真实模型、付款或邮件服务。
